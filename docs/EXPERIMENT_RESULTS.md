# 实验结果

E1、E2 结果来自 2026-10-17，E3 结果来自 2026-10-18 在 conda common
环境中的正式运行。Python 版本为 3.11.17，每个参数组 30 次。原始数据保存在
results/raw，图表保存在 results/plots。这里报告的是随机实验的实际观察结果。

## E1：d/T 与攻击成功率

固定 512-bit 模数：

| 目标 d/T | 成功次数 | 成功率 |
|---:|---:|---:|
| 0.25 | 30/30 | 100.0% |
| 0.50 | 30/30 | 100.0% |
| 0.75 | 30/30 | 100.0% |
| 1.00 | 30/30 | 100.0% |
| 1.25 | 30/30 | 100.0% |
| 1.50 | 30/30 | 100.0% |
| 2.00 | 22/30 | 73.3% |
| 2.50 | 12/30 | 40.0% |
| 3.00 | 9/30 | 30.0% |
| 4.00 | 5/30 | 16.7% |
| 5.00 | 2/30 | 6.7% |
| 8.00 | 2/30 | 6.7% |

观察：

- 边界内的 0.25、0.50 和 0.75 组全部成功。
- 本轮 1.00 到 1.50 仍全部成功，但这不能解释成经典定理对边界外仍有保证。
- 从 2.00 开始，成功率总体明显下降；边界外既有成功样本，也有失败样本。
- 经典边界是满足有关假设时的充分保证，不是“超过边界立即失败”的绝对分界线。
- 30 次仍属于课程规模实验，5.00 和 8.00 同为 2/30 不代表两者真实成功率相同。

## E2：模数位数与攻击耗时

固定目标 d/T=0.75，每组 30 次：

| 模数位数 | 成功次数 | 攻击耗时中位数 |
|---:|---:|---:|
| 256 | 30/30 | 0.179 ms |
| 512 | 30/30 | 0.491 ms |
| 1024 | 30/30 | 1.555 ms |
| 2048 | 30/30 | 6.425 ms |

观察：

- 所有故意生成的弱密钥均被成功恢复。
- 模数位数增大时，本轮攻击耗时随之上升。
- 2048-bit 弱 RSA 仍在毫秒级被恢复，因为攻击利用的是过小 d，而不是暴力分解 n。
- 当前渐近分数实现为容易讲解的从右向左前缀计算，时间复杂度为 O(n²)。
- 表中只测量 wiener_attack(e,n)，不包含素数生成、密钥生成、CSV 或绘图时间。

## E3：普通 RSA 与弱 RSA

固定 2048-bit 模数，弱密钥目标 d/T=0.75，每组 30 次：

| 密钥类型 | d/T 中位数 | 正确恢复次数 | 攻击耗时中位数 |
|---|---:|---:|---:|
| weak | 7.500×10^-1 | 30/30 | 3.740 ms |
| normal | 2.578×10^462 | 0/30 | 0.031 ms |

观察：

- 两组调用完全相同的 wiener_attack(e,n)。
- 弱组 d 接近 Wiener 标尺的 75%，30 组全部恢复。
- 普通组的 d/T 与弱组相差约 463 个十进制数量级，本轮没有恢复任何一组。
- 普通组耗时更短，是因为 e=65537 时 e/n 的连分数很短，攻击很快遍历完并返回
  None；耗时更短不代表它更容易被恢复。
- None 只表示本次 Wiener 攻击没有找到有效候选，不是完整 RSA 安全证明。

## Live Demo

Demo 每次现场生成新的 2048-bit 密钥。弱密钥目标 d/T 为 0.75，生成后应满足
严格 Wiener 边界并恢复 d、phi、p、q；普通密钥使用 e=65537，并用完全相同的
攻击入口验证返回 None。具体大整数和耗时以每次现场输出为准。

## 限制

- 每组 30 次比原来的 10 次更稳定，但仍不能代替大规模统计研究。
- 密钥和计时结果会受随机素数、Python 版本、处理器和机器负载影响。
- 超过 Wiener 经典边界不代表安全，还可能存在其他参数问题或其他攻击。
- Demo 使用随机密钥，因此密钥生成和攻击耗时会随每次运行略有变化。
